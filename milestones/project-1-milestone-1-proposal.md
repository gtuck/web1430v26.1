# Project 1 Proposal – Milestone 1

**Due:** End of Week 5
**Points:** 20
**Category:** Projects (Milestone 1 of 3)

## Purpose

This is the planning checkpoint for [Project 1 – Interactive Style Guide](../projects/project-1-interactive-style-guide.md). Submitting it now means Week 6 is build time instead of decision time, and it gives the instructor a chance to redirect scope before you have written code against a plan that will not work.

## What to submit

Create `projects/project-1/proposal.md` in your course repository. The full requirements are in the **Milestone 1 — Proposal** section of the project brief; in summary, it must contain all six of:

1. Project context — the fictional product or organization, and its audience
2. Colour palette — at least four named colours with hex values and confirmed contrast ratios
3. Typography plan — font families and a scale in `rem`
4. Component list — the five components you will document
5. Rough sketch — hand-drawn or digital, showing how the page is organised
6. Accessibility plan — for each interactive pattern, how a keyboard user operates it and which ARIA attributes communicate its state

This is a planning document. No code is required.

**Submit to Canvas:** your repository URL, plus a direct link to `proposal.md` in the text entry.

## How this is graded

- **All six elements present and specific (20)** — the accessibility plan names real attributes, not "I will make it accessible"; contrast ratios are stated, not assumed
- **Complete but thin in places (15)** — every section is there, one or two are generic
- **Missing an element, or several sections are placeholders (10)**
- **Submitted but substantially incomplete (5)**
- **Not submitted (0)**

Proposals with a vague accessibility plan will be returned with feedback in time to revise before the Week 7 checkpoint.
