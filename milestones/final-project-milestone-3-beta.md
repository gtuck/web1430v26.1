# Final Project Beta Review – Milestone 3

**Due:** End of Week 14
**Points:** 25
**Category:** Projects (Milestone 3 of 5)

## Purpose

A substantially complete, deployed beta of the [Final Project](../projects/final-project-campus-or-community-tool.md), plus an honest self-assessment. Rough edges are expected at this stage. Missing features are not.

This milestone pairs with [Lab 13](../labs/lab13-lighthouse-accessibility-and-deployment.md) — audit this beta rather than a disconnected practice page, and the same notes serve both submissions.

## What to submit

A deployed version with:

- All major features present and functional, rough edges allowed
- Fetch, `localStorage`, and at least two interactions working
- Mobile layout functional
- Loading and error states implemented

Plus a brief self-assessment in the Canvas text entry, answering:

- What is working well?
- What is not yet done or not working correctly?
- What help do you need before final submission?
- Which 2–3 issues from your Lab 13 audit or personal QA pass are the highest priority before Week 15?

**Also start `rationale.md` this week.** It does not need to be polished, but the file should exist with each required prompt as a heading and at least bullet notes underneath, so Week 15 is revision rather than first drafting.

**Submit to Canvas:** the live URL, your repository URL, and the self-assessment as a text entry.

## How this is graded

- **Deployed beta with all major features, specific self-assessment, `rationale.md` started (25)**
- **Deployed beta, self-assessment generic or `rationale.md` absent (20)**
- **Deployed but a major feature is missing (15)**
- **Not deployed (8)** — this is the last checkpoint before the final; an undeployed beta is the strongest predictor of a rough Week 15
- **Not submitted (0)**

An honest "this part does not work and here is what I have tried" scores full marks on the self-assessment. A claim that everything is fine, on a beta where it visibly is not, does not.
