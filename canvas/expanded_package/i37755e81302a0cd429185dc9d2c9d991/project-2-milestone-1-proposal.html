Project 2 Proposal – Milestone 1

Due: End of Week 10
Points: 25
Category: Projects (Milestone 1 of 3)

Purpose

The planning and data checkpoint for Project 2 – Data-Driven Micro-App. Most Project 2 failures are data-shape failures discovered too late. This milestone forces the API question early, while changing your mind is still cheap.

What to submit

Create projects/project-2/proposal.md with the six sections in the order given in the project brief's Milestone 1 section:

  1. Problem statement — who specifically, what task, why it is inconvenient today
  2. API — the endpoint URL, plus one real example of the raw JSON response
  3. Data model — one normalized item as a JavaScript object, each property typed and traced back to the raw response
  4. UI sketch — loaded, loading, and error states
  5. localStorage plan — key name and the shape of the stored value
  6. API viability check — four bullets: CORS/browser access, rate limits or auth, attribution/terms, data reliability

Submit to Canvas: your repository URL, plus a direct link to proposal.md in the text entry.

How this is graded

  • All six sections, problem-first (25) — the problem statement names a specific person and task; real JSON is pasted; the data model maps to it property by property
  • All six present, problem statement generic (20) — "users can search for things" is the failure mode here
  • Missing one section, or the API is untested (15)
  • Substantially incomplete (8)
  • Not submitted (0)

The proposal is reviewed against the problem statement first. A vague problem statement will be returned for revision before you build — that is a feedback step, not a penalty, but it costs you days you will want in Week 12.
